# ③ 否决与避坑档案 (Anti-Patterns & Dead Ends)

本文档记录本项目演进历程中被**实测证明失败、存在严重隐患并彻底否决的技术方案（暗知识档案）**。
严禁将以下已否决方案重新引入代码库。

---

## 避坑总览表

| 编号 | 否决方案名称 | 致命缺陷现象 | 真实技术根因 | 唯一合法解决方案 |
| :--- | :--- | :--- | :--- | :--- |
| **AP-001** | **全树 JavaScript 迁移 TypeScript** | 无法直接注入 Webview、类型冲突升维、增加构建黑盒 | 运行时依赖源码文本提取，打包按源码硬列举；无构建链模型 | 采用 `// @ts-check` + JSDoc 类型注释，零构建步骤 |
| **AP-002** | **直接改写基础渲染视图文件** | 核心界面定制被后续覆盖重写，产生数百行高频冲突 | 单点渲染文件耦合度高，直接修改难以追踪自研边界 | 抽离为 `usage-ui.local.cjs`，通过运行时覆盖注入生效 |
| **AP-003** | **建立平行测试或平行文档体系** | 测试脱离 CI 矩阵、文档产生双重事实导致断链漂移 | 独立平行目录（如 `tests-local/`）不被标准流水线感知 | 就地纳入标准 glob，真理库统一收敛于 `docs/` |
| **AP-004** | **自研变更流水混入上游 CHANGELOG** | 历史版本记录被吞并覆盖，功能演进不可追溯 | 历史文件高频重写与分发策略分歧 | 统一在 `docs/LOCAL_CHANGES.md` 中维护架构决策流水 |
| **AP-005** | **每新增门禁就修改 package.json** | 核心配置文件改动频繁，破坏清单稳定性 | 脚本配置区与构建元数据强耦合 | 仅保留稳定入口，具体门禁清单集中在 `tools/local-gate.mjs` |
| **AP-006** | **使用 git merge 暴力吸收外部更新** | 覆盖式提交引发大面积行级冲突，暗中吞并自研逻辑 | 分支演进线差异巨大，三方自动合并不可靠 | 采用 `git cherry-pick` 单点挑选，明确改动边界 |
| **AP-007** | **搬迁逻辑时仅修改单一加载路径** | 门禁全绿但插件重装或 App 运行时回退至旧版本 | 渲染注入存在多条独立管线（App、IDE、门禁、工具） | 统一通过 `compat/usage-view.mjs` 解析器收口路径 |
| **AP-008** | **硬编码已被删除或不可控的远程仓库地址** | 运行时自动更新与一键安装脚本抛出 HTTP 404 崩溃 | 原上游仓库因不可抗力被删除，硬编码引发单点链路瘫痪 | 统一指向本主维护源 `moumouye/antigrative-dashboard`，提供源码归档降级 |
| **AP-009** | **发布流水线强假设必须包含二进制打包资产** | 纯文本更新发布时抛出 `KeyError: 'assets'` 致命中断 | 发布脚本硬编码要求检验并上传预打包好的 `.zip` 文件 | 引入 `--text-only` 模式，解耦文本日志推送与二进制资产分发 |

## 深度剖析 (Deep Dive)

### AP-001：全树 JavaScript 迁移 TypeScript
* **否决日期**：2026-11-02
* **历史方案**：将 120+ 个 `.mjs` 与 `.cjs` 批量重命名为 `.ts`，引入 `tsc` 编译并建立构建输出目录。
* **致命缺陷**：
  1. 运行时打断：Webview 注入依赖于 `fs.readFileSync` 提取 CommonJS 源码文本；若产物被转译或打包，函数名与全局变量签名将发生畸变；
  2. 零依赖原则破坏：仓库原设计为免构建（Zero-Build），引入 TypeScript 必须引入庞大的编译链与 `node_modules`；
  3. 白名单契约断裂：打包脚本按源文件名硬编码匹配，批量改名将导致打包资产全部丢失。
* **唯一正解**：在文件顶部声明 `// @ts-check`，配合 JSDoc 完成类型提示与约束，配合 `npx -y typescript tsc --noEmit` 进行静态校验。

---

### AP-002：直接改写基础渲染视图文件
* **否决日期**：2026-11-02
* **历史方案**：直接在原始 `compat/usage-ui.cjs` 内编写 24 小时活动图、组件筛选与实时成本测算，产生千行级别的大补丁。
* **致命缺陷**：原始文件是单点入口，一旦基础结构更新，上千行的自研逻辑将产生剧烈的重叠冲突，极难理清自研边界。
* **唯一正解**：将自研看板完整封装至 `compat/usage-ui.local.cjs`；基础文件保持原貌；在宿主注入阶段通过同名变量覆盖生效（`window.__agPulseUsageFactory = localFactory`）。

---

### AP-003：建立平行测试或平行文档体系
* **否决日期**：2026-11-02
* **历史方案**：新建 `tests-local/`、`docs-local/`、`gates-custom/` 等独立平行目录存放自研逻辑。
* **致命缺陷**：
  1. 平行测试从不被主测试驱动器运行，CI 平台无法覆盖，导致测试沦为摆设；
  2. 双份文档必然随着时间推移相互矛盾，形成“薛定谔的规范”。
* **唯一正解**：测试直接放进标准 glob 匹配目录（如 `sidecars/panel/tests/`）；文档统一收敛至 `docs/` 真理库，绝不建立平行体系。

---

### AP-007：搬迁逻辑时仅修改单一加载路径
* **否决日期**：2026-11-03
* **历史方案**：将用量视图迁往新文件时，仅更新了 IDE 加载器和门禁提取点，未修改 App 桌面端的加载源。
* **致命缺陷**：被测代码与门禁同时修改，门禁跑在修改后的路径上全部绿灯，但在真实 Electron 桌面端重新安装后，页面静默降级为旧版本，测试未能防御真实运行态。
* **唯一正解**：创建 `compat/usage-view.mjs` 作为系统内唯一的路径裁决处。所有消费者（App 注入、IDE 注入、门禁脚本、资产渲染）必须全部接入解析器。

---

### AP-008：硬编码已被删除或不可控的远程仓库地址
* **否决日期**：2026-11-06
* **历史方案**：在安装脚本、自动更新 Worker 及发布配置中硬编码指向原上游项目 `YOU-SHOULD-KNOW-ME/antigrative-dashboard`。
* **致命缺陷**：原上游仓库因不可抗力在 GitHub 上被彻底删除（HTTP 404），导致在线一键安装、更新检测、文档超链接全链路雪崩，用户端抛出未捕获的网络错误。
* **唯一正解**：
  1. 全面切换至自主维护源 `moumouye/antigrative-dashboard`；
  2. 安装脚本增加两级容灾：若指定 Release 资产不可用，自动降级至源码主干归档（`main.zip`），绝不直接崩溃退出。

---

### AP-009：发布流水线强假设必须包含二进制打包资产
* **否决日期**：2026-11-06
* **历史方案**：`publish-release.py` 发布脚本在推送 GitHub Release 时，强行断言 `dist/*.zip` 必须存在，并在发布后立即检索返回的 `assets` 列表。
* **致命缺陷**：在某些场景下只需要通过 Release 推送版本更新通知或纯文本日志，无需重新编译打包数兆字节的二进制文件。强行校验导致脚本抛出 `KeyError: 'assets'` 并中断 CI 流程。
* **唯一正解**：在发布工具中正式引入 `--text-only` 纯文本模式契约。在此模式下跳过本地与远程的 Release Assets 检查，支持纯净的版本状态广播。
