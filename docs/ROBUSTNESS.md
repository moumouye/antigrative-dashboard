# 系统鲁棒性与自愈架构规范 (System Resilience & Auto-Healing Spec)

本文档定义 Antigravity Pulse 面向 Electron 宿主程序、独立守护进程（Sidecar）、跨进程通信与前端渲染挂载的全链路鲁棒性防御矩阵与自愈机制。

---

## 1. 核心架构鲁棒性原则 (Core Principles)

1. **宿主非侵入隔离（Host Non-Invasive Invariant）**：
   - 适配器与前端控件部署于独立的用户插件目录，不解包、不修改、不依赖宿主程序的 `app.asar` 归档；
   - 宿主程序版本迭代时，插件逻辑完全解耦，宿主重装或静默升级不会破坏既有数据与配置。
2. **多实例排他与无感交接（Single-Writer & Graceful Handoff）**：
   - 守护进程通过物理锁文件和端口探测确保单实例运行，避免多进程并发争抢；
   - 实例更迭时，旧实例安全释放资源并平滑交接，前端渲染透明重连。
3. **安全自愈与降级呈现（Graceful Degradation）**：
   - 遇到未就绪、端口变动、数据断流或 DOM 几何冲突时，控件采用非破坏性安全降级策略（如收缩为紧凑图标或安全暂隐），绝不阻碍宿主原生界面交互。

---

## 2. 跨平台后台发现与凭据握手 (Discovery & IPC Resilience)

守护进程与本地宿主之间建立跨平台高韧性发现通道：

| 平台环境 | 端口与进程匹配机制 | 容灾策略 |
| :--- | :--- | :--- |
| **macOS** | 通过 `lsof -nP -iTCP -sTCP:LISTEN` 与进程树反查精准提取所属 PID；从进程环境变量（`ANTIGRAVITY_SERVER_CSRF_TOKEN`）提取认证凭据 | 环境变量缺省时尝试降级读取启动参数；重连窗口内保持平滑重试 |
| **Linux** | 从当前用户 `/proc` 进程文件描述符（FD socket inode）匹配 TCP/TCP6 监听端口；读取 `/proc/<pid>/environ` 提取凭据 | 严格按真实有效所属用户隔离，拒绝猜测未知进程 |
| **Windows** | 针对独立 Standalone 进程，执行单次筛选匹配其持有的本地 HTTP 监听端口 | 释放工作目录句柄（CWD），防止文件句柄占用引发权限异常 |

---

## 3. DOM 挂载与前端交互碰撞防御 (DOM Geometry & Collision Guard)

内嵌于宿主界面的状态条与悬浮卡遵循严格的几何安全与碰撞防御机制：

### 3.1 挂载边界锁定
* 以宿主稳定的输入容器（`agent-input-box`）为物理边界，依包含关系定位局部操作行；
* 排除标题栏、非 flex 容器及辅助面板中的无关选择器，杜绝误挂载。

### 3.2 动态碰撞检测与密度自适应
1. **几何相交检测**：
   - 实时检测状态条与宿主原生控件（如模型选择器、新建标签、发送按钮、全屏按钮）的几何矩形；
   - 在相交区域中心与各顶点执行指针命中测试（Hit Testing），确保宿主原生按钮具备最高交互优先级。
2. **响应式密度梯度**：
   - **完整模式 (Full Density)**：空间充足时呈现完整会话统计（TPS、缓存命中、上下文占用、额度信息）；
   - **图标模式 (Compact Density)**：宽度受限时自动收缩为紧凑图标形态，保留核心指标入口与卡片交互；
   - **安全暂隐 (Safe Conceal)**：若在紧凑模式下仍检测到与宿主原生按钮相交，状态条自动隐去，待空间恢复后平滑重现。

## 4. 全链路故障恢复与自愈矩阵 (Fault Recovery Matrix)

| 故障场景 | 防护机制与自愈动作 | 预期终态 |
| :--- | :--- | :--- |
| **宿主静默升级** | 插件驻留于用户独立插件目录，不修改 `app.asar` | 升级后无损恢复运行 |
| **渲染端口 / 窗口变化** | 运行时轮询探测并与目标重新建立 CDP 连接 | 3 秒内恢复握手与挂载 |
| **宿主启动延迟 / 文档替换** | 心跳检查挂载状态，缺失时自动重新注入挂载 | 文档就绪后自动呈现 |
| **切换用户账号** | 按账号哈希建立物理隔离，校验请求代次与当前后台实例代次 | 阻断旧账号请求晚到污染，隔离展现当前账号统计 |
| **守护进程重载 / 重启** | 持久化账本与插件运行时分离；本地统一数据库保持幂等状态 | 历史指标即刻恢复，无断层 |
| **接口超时或断网** | 保留有效已采集样本与上次已知额度，明确标识状态为 `stale` | 界面呈现最后已知准确值，不虚构零额度 |
| **账本文件偶发异常** | 隔离单条异常损坏记录，写入采用临时文件原子替换（Atomic Rename） | 账本全局连续可用，防止写中断造成文件破损 |
| **路由切换与长短会话交替** | 每次导航递增请求代次，作废上一个会话的未决请求（Pending Promise） | 新会话即刻刷新，绝不被旧会话响应回写覆盖 |

---

## 5. 数据持久化与隐私物理红线 (Persistence Invariants)

1. **零正文存储**：仅保存模型标识、时间戳、状态枚举与数值统计指标；严禁向本地磁盘写入用户 Prompt、对话正文、认证密钥或原始通信片段；
2. **账号作用域哈希化**：多账号环境统一使用 `sha256("antigravity:local:unified:usage")` 固化设备级作用域，单机多身份共享统一账本；
3. **版本化迁移自愈**：持久化快照自带算法版本标识（如 `RATE_VERSION`）；遇到规范迭代时，历史快照进入重算状态，重新读取轨迹全量计算更新。
